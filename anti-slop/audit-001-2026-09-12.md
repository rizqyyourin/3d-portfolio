
# Anti Slop audit 001

Date: 2026-09-12
Mode: AFTER
Scope: current portfolio UI and its source. No source files were modified during this audit.

## Findings

### 1. HIGH — Remove em dashes from user-facing copy

Rule: R-02 — Copywriting

Reason: User-facing text contains `—` in journey dates, the journey description, contact copy, and the 3D screen texture. Anti Slop forbids the em dash character outside its own documentation.

Evidence: `src/app/page.tsx:56-60`, `src/lib/journey.ts:3-5`, `src/lib/screen-texture.ts:16-19`.

Suggested scope: replace the punctuation with commas, periods, colons, or parentheses while preserving the supplied meaning.

### 2. HIGH — Establish and record visual direction

Rule: R-37 — Design Direction Required

Reason: The repository has no `DESIGN.md` or equivalent style-direction file, and the UI is not labeled as `draft without direction` with the required dials. The visual direction is currently implicit in CSS rather than recorded as owner-approved guidance.

Evidence: no `DESIGN.md` exists; `AGENTS.md` has no design-direction reference; `src/app/globals.css` defines the palette, typography, glass treatment, and motion without a direction record.

Suggested scope: document the existing owner-approved identity first, or explicitly label the current result as a draft before further visual iteration.

### 3. HIGH — Verify text contrast across the rendered UI

Rule: R-25 — Color Contrast

Reason: The stylesheet uses many muted green-gray text colors on the near-light background, including `#8f9882`, `#909a83`, `#9ca48f`, `#a5ad9b`, `#95a382`, and `#8b9b78`. Their rendered contrast has not been established against every background they pass over, especially translucent surfaces and the 3D scene.

Evidence: `src/app/globals.css:1-10`, plus the repeated muted text declarations in the same file.

Suggested scope: run the contrast checker against the actual rendered states, then darken only the failing text while preserving the palette hierarchy.

### 4. MEDIUM — Reduce or justify backdrop blur usage

Rule: R-10 — Glassmorphism

Reason: `backdrop-filter` is used on the header index control, scene tools, explore hint, object labels, skill labels, milestones, and the dialog overlay. This exceeds the skill's 1–2 element accent cap unless each use is explicitly justified.

Evidence: `src/app/globals.css:5-7`, `src/components/ui/dialog.tsx:9`.

Suggested scope: keep blur only where it separates controls from the 3D scene, and replace lower-priority labels/cards with opaque surfaces.

### 5. MEDIUM — Record the purpose of repeated arrow glyphs

Rule: R-08 — Button Arrows

Reason: `ArrowUpRight`, `MoveUpRight`, and literal `↗` appear across most navigation and CTA controls. The arrows are generally relevant to movement or external action, but their purpose is not documented and the pattern is close to becoming a default identity on every action.

Evidence: `src/app/page.tsx:6,42,46,47,50,56-60`, `src/components/macbook.tsx:44`, `src/lib/screen-texture.ts:16-19`.

Suggested scope: retain arrows where they communicate external navigation or opening a detail view; remove them from actions where the label already communicates the behavior.

## Existing strengths observed

- Loading and model-error states exist in `src/app/page.tsx`.
- Interactive controls have real handlers or destinations; no obvious dead control was found by source inspection.
- Keyboard navigation, visible focus styles, Escape-close dialogs, reduced-motion handling, and mobile overflow assertions exist in `tests/portfolio.spec.ts` and the stylesheet.
- Project, career, and credential content is presented as supplied content; no fake testimonials or unsupported marketing metrics were found.
